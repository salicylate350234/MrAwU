# 这套动画凭什么说自己算得对

三句话：**受力用冲量守恒自检，运动用解析解对照，画面用同一份渲染代码保证一致。**

## 一、受力分解残差 |ΣJ − Δp|

仿真每一步都会把物块受到的所有力按来源分类累加成冲量：

```
J重力 + J法向 + J摩擦 + J绳/杆 + J外力 + J阻尼 = ΣJ
而动量变化 Δp = m·v_end − m·v_start
```

冲量-动量定理保证 `ΣJ` 与 `Δp` 在一帧内**严格相等**，所以

```
残差 = |ΣJ − Δp| / (|ΣJ| + |Δp|)
```

是一个不需要外部参考答案的自检：正常情况是 0.0xx%（浮点与求解器迭代的残差）。

**怎么用这个数**：画面右上角一直显示它。如果它跳到 ~100%，那一定是某个力的**符号或方向**画错了，
而不是引擎坏了。开发过程中它抓到过三个真实的错误：弹簧力方向写反、滑轮反力符号不统一、
以及"忘了关闭刚体休眠"导致静止物体接触力全部归零。

它同时解决了另一个问题：碰撞这类过程只在 1~2 帧内完成，如果按瞬时力采样会随采样时刻剧烈抖动；
用冲量累加就没有这个问题，展示时再除以帧时长换算成平均力。

## 二、解析值 vs 仿真值

每个模型都自带 `expect()`，把教科书公式算出来的值和引擎算出来的值并排显示，并给出相对误差。
它测的是**指定的物理量在指定时间窗口内的平均值**（不是随手抓一帧）：

| 探针类型 | 用途 | 例子 |
|---|---|---|
| `accel` + `project` | 某方向上的加速度 | 斜面 `g(sinθ−μcosθ)` |
| `force` + `comp` | 某个分力在指定方向上的投影 | 支持力 `N = mgcosθ` |
| `mode: 'mag'` | 矢量模长 | 绳张力、向心力 |
| `period` | 过零点测周期 | 简谐运动 `T = 2π√(m/k)` |
| `stat` | 全局统计量 | 动量守恒、机械能 |
| `reduce: 'sum'` | 过程量求和 | 碰撞冲量 `I = ∫F dt` |

**采样窗口是关键**：必须避开"物理已经结束"的阶段（已经落地、已经共速、已经静止），
否则平均值对不上解析解——这类不一致曾经让三个模型误报失败，实际是窗口落在了物块滑出斜面之后。

## 三、画面与数值同源

`lib/draw.js` 是唯一一份渲染代码，浏览器播放器和 `node/qa.mjs` 都调用它。
所以用 `node node/qa.mjs` 导出的 PNG 与老师在浏览器里看到的画面是同源的，
"我看到的就是老师看到的"，不存在"数值对但图不对"的盲区。

QA 图要检查的是：箭头方向是否符合物理判断、有没有被画布边缘裁掉、标签有没有叠在一起。

## 四、当前回归结果

`node node/tests.mjs` 会跑全部模型的多组参数组合，每组的判定标准是：

1. 残差 `|ΣJ−Δp|` 最大值 < 0.5%
2. 所有解析对照项相对误差 ≤ 0.5%（个别过程量 2%）

两者同时满足才算 PASS。改动物理代码后必须重跑，**不允许靠放大容差掩盖错误**。

## 五、已知的精度边界

| 情形 | 说明 |
|---|---|
| 平滑过程（斜面、连接体、简谐、圆周） | 精度最高，可以做到 0.000% |
| 碰撞瞬间的接触力 | 是冲量折算的平均力，会随步长变化；动量与冲量本身精确 |
| 静摩擦 | 求解器的接触约束，不是真静摩擦模型；接近临界角 μ≈tanθ 时有微小抖动 |
| 弹簧 | 显式力积分，周期有 O((ωΔt)²) 的离散误差（实测 < 0.01%） |
| 圆轨道 | 用 n 段边近似（默认 64 段），弦高误差 ≈ R(1−cos(π/n)) |
| 二维 | planck 是 Box2D 的移植，只有平面力学 |
