### 4e. 模型变换 与 视图变换 分开（重要）

渲染管线是**两级**的：`project(view, x, y)` 先过**模型变换** `view.mt`，再过**相机** `view.cx/cy/pxPerM`。

```
世界坐标 --[模型变换: 模型自己的 position/scale]--> 世界坐标' --[相机: 取景]--> 屏幕像素
```

- **控制框（8 个控制点）改的是模型变换**（`scene` 渲染时的 `view.mt = {cx,cy,sx,sy,tx,ty}`），
  不是相机。拖动控制点 → 重算 `sx/sy/tx/ty` → 模型几何整体缩放平移；
  **相机完全不动**（实测拖动前后 `pxPerM` 保持 45.6 不变）。
- 与"相机变焦"的本质区别：相机变焦会**裁掉框外内容**、也改不了模型本身；
  模型变换只动模型，画布上其余部分（网格、其它参照物）原地不动，不会因为放大而丢内容。
- 跟随模型一起变换的：刚体位置/尺寸、轨迹、力与速度箭头（`project` 两端点都过变换，
  所以箭头长度自动跟着缩放）、尺寸标注、场线（`field.js` 的 `proj` 也接了 `view.mt`，
  且 `viewDomain` 会按逆变换折算计算域）。
- 不跟随的：左上/右上的图例与数据条、坐标网格（网格是"纸"，不是模型）、下方的 x-t/v-t 图。
- 旧的 `cropView()`（相机裁剪）保留但**不再使用**，避免以后误用。

### 4f. 右上角"受力小窗"（取代原数据条）

- 画布右上角浮着一个小窗（`.fp`，`position:absolute` **不占布局**，可折叠；传输条上的「受力图」按钮可整体隐藏）。
- 内容是**受力图**：把选中物体受到的各个分力**平移到同一个作用点**画成箭头，
  所有箭头共用同一个比例（由 `freeBodySize` 定标），因此箭头相对长度就是力的相对大小。
- **窗口尺寸随内容自适应**：`freeBodySize()` 先算"箭头包围盒 + 标签余量"，
  调用方据此设置 canvas 尺寸 → 窗口"刚好装下"，不会在画布上占一大块。
  边距要留够（默认 52px），否则箭头旁的数值标签会被窗口边缘裁掉（踩过）。
- **多物体模型**（板块、滑轮…）：小窗顶部有对象下拉，先选对象再显示受力图；
  默认选"当前合力最大"的那个（通常就是主动运动的主体）。
- 原右上角数据条（`drawHud`）不再调用，"右上角数据条"开关也从设置里移除；
  残差等自检数据仍可在下方对照表看到。

### 4g. 受力小窗的坐标系（整系旋转 + 正交分解）

小窗里画的是**受力图 + 正交分解**。关键：**旋转的是坐标系，不是力**——
屏幕上的坐标轴按题型倾斜，力的箭头始终是它的**真实方向**，非轴上的力从箭头尖端向两条轴作虚线垂足。

| 题型 | 坐标系 | 怎么来的 |
|---|---|---|
| **斜面**（incline / inclinePush） | **整系旋转**：x 轴沿斜面向下、y 轴为斜面外法向 | 模型声明 `analysisAxis: [x̂, ŷ]`（x̂ 给"沿斜面**上升**方向"、ŷ 给外法向）；播放器按整段位移把 **x̂ 翻成沿斜面向下**，**ŷ 不翻**（始终指向远离斜面一侧） |
| 其余全部（平抛、类平抛/偏转电场、圆周、板块、弹簧、滑轮…） | **世界水平竖直** | 不声明 → `[[1,0],[0,1]]` |

要点（都踩过）：

- **别把力转到坐标系里**：那样得到的是"坐标轴水平、力被歪着画"，与画布上的真实方向对不上，
  老师一眼就会觉得不对。要的是坐标轴歪、力保持原方向。
- **别一律取"当前速度方向"当 x 轴**：类平抛速度方向一直变、圆周更是每帧在转，坐标轴会乱转。
- **y 轴必须单独给**（不能用 x̂ 转 90° 推）：x̂ 翻成"向下"之后，靠旋转公式得到的 ŷ 会指向斜面**内部**。
  由模型给出外法向 `[−sinθ, cosθ]` 最稳。斜面题的正确结果是：
  重力 20 N 分解为沿斜面 +10.00 N 与垂直斜面 −17.32 N，支持力 17.32 N 全落在 +y，合力 6.54 N 全落在 +x。
- **轴的解析要兼容两种写法**：`[x̂]` 与 `[x̂, ŷ]`。改声明格式时别忘了同步 `motionAxis`，
  否则 `along` 会算成 `NaN`、翻转静默失效（面板上 x 轴就会反向）。
