# MrAwU 优化基线（Phase 0）

> 本文只记录**现状与实测口径**，不含改动方案。数据由 `node/cost.mjs` 从 DSH 会话日志生成，可复跑。
> 测量日期：2026-10-14；被测日志：`C:\Users\wakx\.dsh\sessions\--C-Users-wakx-...--\<会话id>\session.v4.jsonl.zstd`

## 1. 背景：真正的瓶颈是"已有模型的组合"题型

用户的真实痛点不是"新模型做不出来"，而是**把已经做好的模型拼在一起**的题，例如：

> 物块从斜面滑下 → 平滑进入竖直圆轨道**内壁** → 整个装置处于水平匀强电场中

这类题历史耗时约 **20 分钟/题**。它**与会话长短无关**：不是"聊久了上下文变慢"，
而是新装 skill 的**第一题**就要 20 分钟——所以瓶颈在能力缺口，不在上下文长度。

## 2. 已确认的根因缺口（4 条）

| # | 缺口 | 说明 |
|---|---|---|
| **A** | 缺少「轨道」抽象 | 没有"线段 + 圆弧、相切拼接、按弧长参数化"的通用轨道模型；斜面、圆轨道、平抛面各写各的几何，拼接处只能靠手算坐标。 |
| **B** | 圆轨道接触形态不完整 | `lib/models/motion.js` 的 `circular` 只有**杆约束**（`rodLaws`，杆可推可拉）；内壁形态只有独立的 `circTrack`（`shape.kind='track'`，192 段内接多边形），既不是通用"内壁约束"，也不能被组合器复用。 |
| **C** | 电场绑死在两个独立模型上 | 匀强场以 `field.uniform` 写死在 `efieldAccel`（加速电场）、`efieldDeflect`（偏转电场）两个模型内部（`lib/models/electric.js`），无法"套在任意模型上"；点电荷系 `efield` 又是另一套。 |
| **D** | 组合只支持一维链条 | `lib/compose.js` 的 `chain()` 每阶段必须声明单轴 `axis/dir/x0/x1/y0/y1` 并提供 `aAxis(S)` 解析加速度；`solveAxis()` 按坐标穿越切停。**几何拼接型**（圆弧转向、非单调坐标）套不上这个模型。 |

## 4. 度量口径与目标

- **主指标（组合题型）**：从「题图 → 出图（可交付 HTML）」的**墙钟时间**。本次用"含题图的那一轮"近似，历史基线 **≈ 20 min/题**（用户报，未埋点）。
- **副指标**：该轮的 `totalTokens`（上下文规模）与工具调用次数／`pwsh` 耗时。
- **目标**：优化后由**实测**重新标定，本阶段不预设数字。
- 说明：`totalTokens` 里 98.6% 是 `cacheReadTokens`（上下文重放），所以"上下文规模"和"api 计费"必须分开看。

## 5. 本次未测量的部分（诚实边界）

1. **出图墙钟没有埋点**：没有"题图→成品 HTML"的显式标记，只能按用户两次发言的间隔近似（含用户阅读与打字时间），不是纯机器耗时。
2. **阶段 token 是估算**：把每个 step 的 usage 按该 step 内 tool call 数**均摊**，只可用于排序，不可当账单。
3. **子代理再下游未计入**：本次目录里子代理会话（`a5c141e5`、`41e22d0d`）已单独统计，但它们内部再嵌套的下游会话日志未纳入。
4. **只有一台机器的 3 个会话**：样本极小，且含大量与本题型无关的工作（打包、发版、UI 调整）。
5. **缓存计费未知**：`cacheReadTokens` 与 `inputTokens` 的单价差异未做估算，"优化 token"的省钱幅度无法换算成金额。
6. **真实用户输入是近似值**：脚本把 `user/message` 中排除"运行时上下文/压缩检查点/子代理通知"后的条数记为"真实用户输入"（59 条），人工核对主会话实际人类发言约 **49 条**。
7. **`spanMs` 不可用作工时**：含跨天挂机（最长一段 1,962 min），本文的墙钟只用 turn 首尾累加。
