# 场可视化（field）与模组组合（compose）

> 从 `SKILL.md` 移出（原文逐字保留）。什么时候读：做静电场/匀强电场类模型，或要把两个模组首尾接起来时。

### 4c. 场可视化类模型（静电场）：探针与交互

静电场没有动力学，物理全在 `E(r) = Σ kqᵢr̂ᵢ/rᵢ²` 与 `V(r) = Σ kqᵢ/rᵢ` 里，所以：

- 场景里放 `field: { charges:[{x,y,q}], k }`，电荷同时作为**静态刚体**存在（打 `overlay:true`，
  本体由 `lib/field.js` 画成带 +/− 号的圆）；
- 两类新探针：`kind:'fieldAt'`（在指定点重算 E 或 V）与 `kind:'chargeCount'`。
  **探针走 `lib/field.js` 的实现，期望值走模型侧独立实现的同一公式**，两条路径互相对拍；
  对称排布（等边三角形、正方形）在几何中心的场强必须**恰好为 0**，那是真正的物理判据；
- `verletOnly: true`：planck 侧没有"点电荷场"这种力，自检只对解析解；
- `noGraph: true`：隐藏 x-t/v-t 图（与时间无关）；
- 交互（播放器负责）：**拖动电荷/场点、右键删除、设置面板里新增（选种类＋电量）**，
  电荷列表通过 `models.scene(id, params, sceneLib, {charges, probes})` 传入，改动后重算场几何。
- **取景锁定**：场可视化模型的取景不随电荷变化重新适配（否则每拖一下整个坐标系都在缩放平移，
  根本没法摆电荷）。只有换模型/换预设/点"重新取景"时才重新适配。动力学模型照旧自动适配轨迹。
- **计算域 = 当前取景的世界矩形**（再多留 8%）：电场线因此**一直画到画布边缘**。
  早先用"电荷包围盒 + 60%"当计算域，画面上会看到场线突然消失、围成一个突兀的方框。
- 电场线用**自适应步长的 RK4** 追踪（步长按到最近电荷的距离缩放，近处细、远处粗），
  所以电荷靠得很近时也不会出现折线。**RK4 只用在这里**；动力学一律是 `verlet.js` 的速度-Verlet。
- 场点（`field.probes`）：在指定位置按"力的表示方式"画场强箭矢 + 数值，
  参考长度取所有场点 |E| 的 95% 分位。

**匀强电场（有动力学）**：`efieldAccel` 加速电场、`efieldDeflect` 偏转电场。
恒力 F = qE = qU/d ⇒ 速度-Verlet 对它是**精确**的，所以对照项能做到 0.000%。
两个必须注意的地方（都踩过）：

| 坑 | 现象 | 正确做法 |
|---|---|---|
| 用**位置**判断"是否还在场区" | 事件把子步切在 x = d 上，但此刻 x 实际是 d − 1e-16，`x < d` 仍为真 → 出界那半步又加了一次力，末速度多 0.00088 m/s（0.069%） | 用**中点时刻**判断：`inside = t < tEnd`，与 `nextEvent` 的分割严格一致 |
| 电势能在零场区还继续变化 | 漂移段的"机械能守恒"假性不成立（差 1.8e-4 J） | 零场区里 U 取**出场点**的值并保持常量：加速场用 `Math.min(x, d)`，偏转场用 `x < L ? y : −y₁` |

偏转电场还额外核对了教材里的几何定理 **Y = tanθ·(L/2 + D)**（偏转后反向延长线过极板中点），
并带物理校验：若参数使 y₁ > d/2（粒子会打在极板上），模型**直接报错**而不是画出穿板而过的假动画。

> 顺序陷阱（踩过两次）：`lib/field.js` 必须在 **`verify.js` 与 `draw.js` 之前**内联，
> 否则浏览器端 UMD 在加载时取不到 `PFA.field`，表现为"场线静默不画"。

### 4d. 模组组合的标准接口（lib/compose.js）

把两个模组首尾接起来时最容易错的三件事：**几何不接**（B 的场/摩擦作用在错误位置）、
**接口处速度无故突变**（B 的约束一激活就把径向速度吃掉）而冲量没记账、**时间基准没对齐**。
所以接口做成了声明式 + 可校验：

```js
var ch = compose.chain({ stages: [
  { id:'accel', title:'加速电场', axis:'x', dir:1, x0:0, x1:d1, obj:'ion',
    aAxis:function(S){ return a1; },          // 沿轴加速度 → 组合器据此**精确**停在出口
    force:function(t,S){ return parts(...); }, // 阶段内力分解，与单模组同构
    potential:function(t,S){...},             // 可选：电势能（跨接口自动接基准）
    nextEvent/onEvent/project,                // 可选：阶段内部临界点 / 约束
    jump: null,                               // 若接口处**必须**速度突变，在此声明（并据此记账）
    expect:function(p,w){ return [...]; } },  // 自身对照项；w={t0,t1,dt} 由组合器给出
  { id:'deflect', ... x0:d1, x1:d1+L, ... },
  { id:'screen', x0:xScreen, x1:xScreen+1e-9, enter:function(t,S){ S.ion.vx=0; S.ion.vy=0; } }
]});
scene.laws = ch.laws; scene.markers = ch.markers(); scene.compose = ch;
```

组合器提供五件事：

| 能力 | 说明 |
|---|---|
| `checkInterface()` | **静态校验**：相邻阶段的出口/入口必须重合（差一点直接报错），横向坐标也要对齐 |
| `ch.laws` | 按位置分派各阶段的力；到出口用 `solveAxis` 解析求时间**精确切停**；事件里切换阶段并记录交接 |
| `ch.markers()` | 每个接口在时间轴上打一个断口，注明交接点、交接速度、是否声明了突变 |
| `ch.expect(p,{frames})` | 各阶段对照项按阶段时间窗**自动裁剪**（避免用 A 的窗口量 B 的量）+ 接口一致性对照项 |
| `interfaceItems()` | 把接口本身变成机器可校验的量：**交接点重合 / 速度连续 / 突变已记账（ΣJ=mΔv）** |

**接口的记录值是精确边界状态**（在事件里抓，不受 1/60 s 帧采样影响），
所以阶段出口量（出板偏移、交接速度）直接读 `{kind:'interface', which:'state'}` 比从帧里凑准得多。

踩过的五个坑（都写在代码注释里）：

| 坑 | 现象 | 正确做法 |
|---|---|---|
| 只用 `idx = stageIndexFor(S)` | 刚碰到出口索引就跳下一段，"记录交接"永远在看新阶段的出口 → 一个 handoff 都记不到 | 显式把索引推进与"记录"分开 |
| 交接状态取子步**中点** | 子步预测点先碰到边界，记下的是中点值（出板偏移偏 0.9%） | 事件里用精确边界状态**刷新**该条记录 |
| 窗口卡在阶段结束时刻 | 1/60 采样下接口附近一帧都命中不到 → 探针回落全帧（偏 286%） | 窗口两端都留 ±1~3 帧余量 |
| `expect` 里重建场景 | 阶段时间表在新实例上是空的 → 窗口全 NaN（加速度测成 45%） | 用**刚刚跑过的那一份**场景（`ctx.scene.compose`） |
| `handoffs()` 返回 filter 后的新数组 | 场景规范化时拿的是快照，运行期记录看不见 | 返回**同一个数组对象** |

> 组合模型的接口精度直接受子步长度影响：`subSteps` 从 8 提到 24，快速情形的接口偏差从 2% 降到 1% 以内。
